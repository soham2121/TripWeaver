# Days at the destination Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A road trip can include N days at the destination B, planned server-side as a read-only itinerary inside the road-trip result, shown, saved, shared and printed with it.

**Architecture:** A pure `StayPlanner` (backend, `roadtrip/`) turns the road-trip request plus its arrival into an `ItineraryRequest` (arrival rule, inputs carried over) and wraps the outcome in `RoadTrip.Stay`. `RoadTripService` finds B's catalogue and runs `ItineraryPlanner` after `RoadTripPlanner`. The frontend adds the form field, renders `ItineraryView` read-only under the drive, and the road-trip PDF prints the stay days through a shared print body.

**Tech Stack:** Java 21 / Spring Boot (records, JUnit 5, MockMvc on H2), React 19 + TypeScript, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-25-stay-days-design.md`

## Global Constraints

- Leave everything uncommitted (user instruction); no commit steps are run.
- `stayDays` 0–14; blank/0 = no stay; outside the range → `400 BAD_STAY_DAYS`, message `stayDays must be 0..14`.
- Arrival rule: arrival time ≤ 14:00 → stay day 1 = arrival date, day 1 starts at max(09:00, arrival + 60 min); otherwise stay day 1 = arrival date + 1.
- B's catalogue = destination whose catalogue holds the place nearest to B, if within 20 km.
- No place data note, exactly: `No place data near <B>: the stay is counted, but its days are not planned.`
- No interests ticked = every interest in `OsmCategoryMapper.INTERESTS` at weight 3.
- Stay seed = road-trip seed. Stay is read-only (no `onEdit`).
- A stay problem never fails the road trip: it becomes a road-trip warning and a stay with `itinerary = null`, `note` = the message.
- Only one print sheet per page.
- Dark mode remaps Tailwind scales; no `dark:` variants. Backend build target Java 21.

## Review Focus

1. Arrival exactly at 14:00 counts the arrival day (Task 1 test `arrivalAtTwoCountsTheArrivalDay`).
2. Arrival at 13:30 makes day 1 start at 14:30 and still leaves ≥ 60 min before 19:00 (Task 1 test asserts the override; a 18:30 arrival is the next-day branch).
3. B outside Goa/Konkan (e.g. a Pune destination) returns the road trip with a stay note, not an error (Task 2 API test).
4. Old saved road trips without `stay` still render (Task 3 test renders `roadTripResponse()` without `stay`).
5. Road-trip PDF with a stay has exactly one print sheet and lists drive days then stay days (Task 4 test counts regions).

- Test: `backend/src/test/java/com/tripweaver/roadtrip/StayPlannerTest.java`

**Interfaces:**
- Produces: `RoadTrip.Stay(int days, LocalDate firstDay, LocalDate lastDay, int nights, String destination, Itinerary itinerary, String note)`. `nights` = `lastDay + 1 − arrival date` (sleep at B from the arrival night up to the morning after `lastDay`).
- Produces: `RoadTrip withStay(Stay stay)` on `RoadTrip` (copy with the stay set).
- Produces: `static LocalDate StayPlanner.firstDay(LocalDateTime arrival)`, `static LocalTime StayPlanner.firstDayStart(LocalDateTime arrival)` (null when day 1 is the next date), `static ItineraryRequest StayPlanner.request(RoadTripRequest req, LocalDateTime arrival, String destination, long seed)`, `static RoadTrip.Stay StayPlanner.stay(RoadTripRequest req, LocalDateTime arrival, String destination, Itinerary itinerary, String note)`.
- `request(...)` mapping: `destination`, `startDate = firstDay`, `days = stayDays`, `partySize`, `interests` (all `INTERESTS` at 3.0 when empty), `baseLat/baseLon/baseName` from `req.destination()`, `transport`, `pace = BALANCED`, default day window, `returnToBase = true`, `costs = new Costs(foodPerPersonPerDay, null, fuelPricePerLitre, mileageKmPerLitre, null)`, `dayOverrides = [DayOverride(1, firstDayStart, null, null, null)]` when `firstDayStart != null`, `seed`. Everything else null.
- Ruling to record in the ledger at execution: accommodation is left out of the stay itinerary's costs because the itinerary budget counts `days − 1` nights, which undercounts a stay; `nights` is reported on the stay instead and the UI multiplies it by the user's nightly rate.

  - `lateArrivalStartsNextMorning`: arrival 18:30 → `firstDay` 2026-12-16, `firstDayStart` null.
